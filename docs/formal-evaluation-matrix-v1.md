# 正式评测矩阵 v1

## 实验目标

前面的实验已经产生多种证据：Baseline 成功、真实 Recovery、文件级消融和负面案例。如果把它们直接相加成一个总成功率，会混淆不同问题。本阶段把已有报告统一成一张矩阵，但为每类实验保留自己的分母。

## 判定规则

```text
任务成功 = completed=true 且最终 tests_passed=true
Recovery 成功 = 首次测试失败 + 有效生产 diff + 最终测试通过
修改但失败 = 有生产 diff 但最终隐藏测试失败
```

是否修改了两个文件是跨文件证据的一部分，但不能替代最终测试通过。

## 当前矩阵

| 实验组 | 样本数 | 主要结果 |
| --- | ---: | --- |
| Baseline | 14 次尝试 / 10 个任务 | 11 次成功，3 次基础设施失败，有效成功率 100% |
| 故障注入 | 4 个案例 | Middleware 重试 1，模型纠错成功 2，失败 1 |
| 真实 Recovery | 9 次运行 | 最终通过 9，失败后恢复 5，测试前编辑 3 |
| 跨文件消融 | 8 个变体 | 双文件通过 2，其他变体失败 6 |
| 跨文件负面 | 2 个案例 | 修改但失败 2，分类全部正确 |

机器可读结果见 [formal-evaluation-matrix-v1.json](../evals/reports/formal-evaluation-matrix-v1.json)，摘要见 [formal-evaluation-matrix-v1.md](../evals/reports/formal-evaluation-matrix-v1.md)。

## 结论边界

矩阵已经能回答：运行是否成功、失败后是否恢复、两个跨文件是否都必要、修改但失败是否被正确识别。它仍然不能估计大型真实仓库中的总体恢复率，因为任务数量、任务复杂度和模型重复次数都有限。

下一步应扩充正式任务集，并对关键真实任务重复运行，而不是继续把不同实验的数字合并成一个百分比。

## 工程实现

`evals/formal_matrix.py` 只读取已有 JSON 报告，不重新调用模型。这样重新生成矩阵不会消耗 DeepSeek 额度，也不会改变历史运行结果。
